# 악보 캔버스 보관과 그림 동기화

## 화면 동작

첫 페이지는 이미지와 그림이 준비되는 대로 표시합니다. 예배에 들어오면 모든 페이지의 확정 선과 진행 중인 선을 전체 구독 한 번으로 받고, 모든 악보 이미지도 바로 준비합니다. 첫 페이지 이미지의 우선순위를 높이며, 나머지 페이지의 준비가 끝날 때까지 첫 페이지를 숨기지 않습니다.

페이지마다 별도 캔버스를 같은 React 부모 아래 유지합니다. 미리보기에서 본 화면으로 전환할 때는 위치와 활성 여부만 바꿉니다. 초기 준비 중에는 `악보 준비 3/10`처럼 전체 진행 상황을 표시합니다. 아직 준비되지 않은 페이지를 선택하면 현재 화면을 유지하고, 사용자가 새 이동을 요청하면 이전 대기를 취소합니다. 준비가 끝난 페이지는 예배를 나갈 때까지 회수하지 않습니다.

그림 변경은 공용 작업 캔버스에서 기존 순서로 합성한 후 표시 캔버스에 복사합니다. 형광펜과 지우개 결과를 보존하기 위해 부분 덧그리기는 하지 않습니다. 변경 없는 전환은 재합성하지 않으며, 동기 합성 중에는 준비 상태를 불필요하게 토글하지 않습니다.

## 데이터와 메모리

- `DrawingSession`은 예배에 속한 전체 페이지의 확정 그림, 진행 중인 선, 서버 확인 전 편집을 보관합니다. 없는 키는 미로딩, 빈 배열은 그림이 없는 페이지입니다.
- `drawings:subscribe`는 `{ worshipId, subscriptionId }`를 받고, `drawings:state`로 빈 페이지를 포함한 전체 그림을 반환합니다. 페이지별 `inProgress`에는 그리는 중인 선의 누적 좌표와 소유 소켓을 포함합니다. 이후 시작·이동·취소·완료·삭제 이벤트를 예배 구독자에게 중복 없이 전달하므로 다른 페이지를 보는 사람과 중간 입장자도 같은 선을 받습니다.
- 새 클라이언트는 페이지별 HTTP 조회, `join:sheet` 및 페이지별 선읽기를 사용하지 않습니다. 서버의 기존 조회/페이지 방은 이전 클라이언트 호환용으로 유지합니다. 서버 임시 선의 소유권은 소켓·페이지·선 ID로 구분하며, 이동 처리에는 DB 접근이 없습니다.
- 진행 좌표는 16ms 간격으로 묶어 보내되, 움직임이 멈춰도 마지막 좌표를 예약 전송합니다. 취소·완료·페이지 이탈 때 예약을 정리하여 종료 후 선이 다시 나타나지 않게 합니다.
- 요청 세대가 다른 조회 응답은 무시합니다. 추가·삭제·전체 삭제는 개별 확인 응답으로 확정하거나 되돌립니다. 재연결·재시도 조회는 소켓에 이미 전송한 편집까지 서버 상태와 맞추며, 별도 편집 재전송 큐는 두지 않습니다.
- 그림 데이터와 모든 페이지의 캔버스는 예배 이탈 때 해제합니다. 일부 캔버스를 회수하던 8페이지·64MiB 정책은 제거했습니다. 보통 10페이지 이하의 예배를 기준으로 기존 DPR 선명도를 유지하며, 실제 픽셀 메모리는 페이지 수에 비례합니다. 기기 자원 확보에 실패하면 오류와 재시도를 제공하며 다른 페이지를 자동으로 회수하지 않습니다.
- 비활성 페이지는 입력을 받지 않습니다. 자신의 진행 중 획은 페이지 이탈·연결 종료 시 취소하고, 포인터 캡처도 해제합니다. 다른 사람의 진행 중인 선은 페이지를 넘겨도 계속 보관·갱신합니다. 서버도 취소·저장 실패·소유자 연결 종료·페이지 삭제 때 임시 선을 정리합니다. 모든 페이지를 해제하면 공용 작업 버퍼도 해제합니다.

## 검증 실행

프로젝트의 Node.js 24 환경에서 실행합니다.

```sh
npm ci
npm --prefix server ci
npm --prefix client ci
npm --prefix client exec -- playwright install chromium webkit
npm run check
npm --prefix server test
npm --prefix client test
npm run build
npm --prefix client run test:e2e
```

브라우저 테스트는 실제 서버 진입점·라우터·Socket.IO와 별도 메모리 SQLite를 사용합니다. 업로드 파일은 테스트 전용 임시 폴더에 만들고 서버 종료 시 정리합니다. 전용 포트는 서버 3197, 클라이언트 5197이며 기존 서버를 재사용하지 않습니다.

브라우저 조합은 Chromium·WebKit 각각 태블릿 834×1194/DPR 2, 모바일 390×844/DPR 3입니다. 왕복 시 동일 캔버스 유지와 프레임별 알파 픽셀, 첫 페이지 우선 표시, 로딩 대기·취소·방향 반전, 다른 페이지 편집, 펜/형광펜/지우개, 실행 취소, 재연결, 전체 화면 보관·중간 입장·이탈 후 자원 해제 및 크기 변경을 확인합니다.

보고서와 화면 캡처는 `output/playwright/`에 생성됩니다. 자동화 결과는 실제 iPad의 Apple Pencil·손바닥 입력 검증이나 테스트/운영 환경 배포를 대신하지 않습니다.
