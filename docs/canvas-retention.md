# 악보 캔버스 보관과 그림 동기화

## 화면 동작

첫 페이지는 이미지와 그림이 준비되는 대로 표시합니다. 나머지 페이지의 그림은 같은 예배의 전체 구독으로 백그라운드에서 받습니다. 첫 이미지가 실패하거나 사용자가 다른 페이지를 선택한 경우에도 전체 구독을 시작할 수 있습니다.

페이지마다 별도 캔버스를 같은 React 부모 아래 유지합니다. 미리보기에서 본 화면으로 전환할 때는 위치와 활성 여부만 바꿉니다. 준비되지 않은 페이지는 현재 화면을 유지하며 준비하고, 사용자가 새 이동을 요청하면 이전 대기를 취소합니다.

그림 변경은 공용 작업 캔버스에서 기존 순서로 합성한 후 표시 캔버스에 복사합니다. 형광펜과 지우개 결과를 보존하기 위해 부분 덧그리기는 하지 않습니다. 변경 없는 전환은 재합성하지 않으며, 동기 합성 중에는 준비 상태를 불필요하게 토글하지 않습니다.

## 데이터와 메모리

- `DrawingSession`은 예배에 속한 전체 페이지의 확정 그림과 서버 확인 전 편집을 보관합니다. 없는 키는 미로딩, 빈 배열은 그림이 없는 페이지입니다.
- `drawings:subscribe`는 `{ worshipId, subscriptionId }`를 받고, `drawings:state`로 빈 페이지를 포함한 전체 그림을 반환합니다. 이후 완료·삭제 이벤트는 페이지 참여자와 예배 구독자에게 중복 없이 전달합니다.
- 전체 로딩 이후 `join:sheet`의 `withState: false`는 그림을 재조회하지 않고 실시간 그리기 방에만 참여합니다. 진행 중인 획 이동은 현재 페이지에만 전파합니다.
- 요청 세대가 다른 조회 응답은 무시합니다. 추가·삭제·전체 삭제는 개별 확인 응답으로 확정하거나 되돌립니다. 재연결·재시도 조회는 소켓에 이미 전송한 편집까지 서버 상태와 맞추며, 별도 편집 재전송 큐는 두지 않습니다.
- 그림 데이터는 예배 이탈 때 해제합니다. 캔버스는 현재·전환 대상·인접·최근 방문 순으로 보관하며, 최대 8페이지와 공용 버퍼 포함 64MiB를 회수 기준으로 사용합니다. 현재·전환 대상은 보호하므로 이 기준을 일시 초과할 수 있습니다. 회수한 화면은 보관한 데이터로 다시 그립니다.
- 비활성 페이지는 입력을 받지 않습니다. 진행 중 획 취소와 포인터 캡처 해제는 이전 페이지 방에서 수행합니다. 모든 페이지를 해제하면 공용 작업 버퍼도 해제합니다.

## 검증 실행

프로젝트의 Node.js 24 환경에서 실행합니다.

```sh
npm ci
npm --prefix server ci
npm --prefix client ci
npm --prefix client exec -- playwright install chromium webkit
npm run check
npm --prefix server test
npm --prefix client test
npm run build
npm --prefix client run test:e2e
```

브라우저 테스트는 실제 서버 진입점·라우터·Socket.IO와 별도 메모리 SQLite를 사용합니다. 업로드 파일은 테스트 전용 임시 폴더에 만들고 서버 종료 시 정리합니다. 전용 포트는 서버 3197, 클라이언트 5197이며 기존 서버를 재사용하지 않습니다.

브라우저 조합은 Chromium·WebKit 각각 태블릿 834×1194/DPR 2, 모바일 390×844/DPR 3입니다. 왕복 시 동일 캔버스 유지와 프레임별 알파 픽셀, 첫 페이지 우선 표시, 로딩 대기·취소·방향 반전, 다른 페이지 편집, 펜/형광펜/지우개, 실행 취소, 재연결, 메모리 회수 및 크기 변경을 확인합니다.

보고서와 화면 캡처는 `output/playwright/`에 생성됩니다. 자동화 결과는 실제 iPad의 Apple Pencil·손바닥 입력 검증이나 테스트/운영 환경 배포를 대신하지 않습니다.
